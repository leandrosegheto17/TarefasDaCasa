## 1. Plano de execução
**Reaproveitamento:** USAR `emTransacao(fn)` e a fábrica de conexão de `backend/api/src/infraestrutura/banco/conexao.ts` (TP-0003) — não abrir segunda conexão `postgres`. USAR a validação de variáveis de `backend/api/src/infraestrutura/config.ts` (TP-0003); se a função que valida uma variável estiver presa à config da API, EXTRAIR um `lerVariavel(nome)` comum e usar nas duas configs. ACRESCENTAR passo ao `.github/workflows/ci.yml` (TP-0002), sem reescrever os existentes.
**Camada:** `backend/api/src/infraestrutura/banco/migracoes.ts` (único SQL: cria `migracao_aplicada` se faltar, lista aplicadas, aplica um arquivo com `sql.unsafe` + insert do registro); `backend/api/src/infraestrutura/trava-host-local.ts` (função pura); `backend/api/scripts/migrar.ts` e `backend/api/scripts/checar-migracoes.ts` (entradas finas; o parser fica numa função exportada e testável). `backend/api/migracoes/` nasce vazia (com `.gitkeep`).
**Referência visual** (só tela/componente): não se aplica

1. TDD da trava: `exigirHostLocal(url, { producao, confirmar })` aceita só `localhost`, `127.0.0.1`, `::1`; com `--producao` exige confirmação (interativa: digitar o host). Sem TTY, só aceita no workflow de deploy da `main` (G-08). PENDENTE: o critério para reconhecer o `deploy.yml` sem TTY ainda não está definido. Proposta: `GITHUB_ACTIONS=true` + `GITHUB_REF=refs/heads/main` + `GITHUB_WORKFLOW` igual ao nome do workflow do TP-0097. Confirmar com o Coordenador.
2. TDD do planejador puro `planejarMigracoes(arquivos, aplicadas)`: ordena por `NNN`; recusa nome fora de `^\d{3}_[a-z0-9_]+\.sql$`, número repetido, hash diferente de um já aplicado e aplicado cujo arquivo sumiu. Hash = SHA-256 dos bytes.
3. `migrar.ts`: lê `DATABASE_URL_MIGRACAO` (papel dono, ADR-002), que entra em `backend/.env.example`. Roda a trava antes de conectar. Cada pendente vai num `emTransacao` próprio com `pg_advisory_xact_lock` (dois deploys ao mesmo tempo). Reexecutar não tem efeito.
4. TDD de `analisarMigracao(texto)`: tira os comentários `--` e `/* */` (aninhados) e os literais `'...'` antes de procurar `DROP`, `RENAME` e `ALTER ... TYPE` (sem diferenciar maiúsculas, em várias linhas). O corpo `$$...$$` **é** varrido, porque executa. O marcador só vale como comentário de linha `-- contrair: <motivo>` com motivo não vazio. Arquivo vazio falha. Erro de leitura sai com código ≠ 0.
5. Adicionar `checar-migracoes` ao script `checar` da raiz (criar o script se o TP-0002 não o criou) e um passo no `ci.yml`.
- NÃO usar ORM nem lib de migração (ADR-002). NÃO importar `postgres` fora de `infraestrutura/banco/` (G-05). NÃO criar tabelas de negócio aqui.

## 2. Plano de teste
- Unit (`backend/api/test/unit/trava-host-local.test.ts`), matriz §9: `LOCALHOST` e `[::1]` aceitam. Devem recusar: `localhost.evil.com`, `127.0.0.1.nip.io`, `evil.com#@localhost`, `postgres://u@localhost@evil.com`, multi-host `localhost,evil.com`, `?host=evil` na query, URL sem host (cai no `PGHOST`), socket unix, URL malformada e `--producao` sem confirmação ou sem TTY fora do critério do item 1.
- Unit `planejarMigracoes`: ordem 001 < 002 < 010, nome inválido, número duplicado, hash alterado, aplicado sumido, nada pendente.
- Unit `analisarMigracao`: `drop`/`DrOp`; `DROP` só em comentário (passa); `'DROP'` em string (passa); `DO $$ ... DROP ... $$` (falha); `ALTER TABLE x\n ALTER COLUMN y TYPE int` (falha); `RENAME` com marcador (passa); marcador dentro de string ou sem motivo (falha); arquivo vazio (falha); arquivo ilegível (sai com código ≠ 0).
- Prova manual contra o Postgres local do TP-0003: migrar duas vezes com uma migração de exemplo temporária, que é removida depois. O registro vai no `## 4`.
- Comando: `pnpm --filter @tdc/api exec vitest run test/unit/trava-host-local.test.ts test/unit/migracoes.test.ts test/unit/checar-migracoes.test.ts`.

## 3. Plano de validação de segurança
- G-08: a trava roda **antes** de abrir a conexão. Conferir no diff que `migrar.ts` não tem caminho que pule a trava e que a falha fecha (exceção, nunca aviso).
- G-06: o hash impede editar uma migração aplicada, e a guarda falha fechada.
- `sql.unsafe` só em `banco/migracoes.ts`, só com o conteúdo de arquivo versionado, nunca com entrada externa. Nenhuma credencial em log: a mensagem de erro mostra só o host.
- A URL do papel dono só existe em variável de ambiente. O `.env.example` não leva valor real (G-29, `gitleaks`).
