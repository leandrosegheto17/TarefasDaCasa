**Reaproveitamento:** USAR `criarApp(config)` de `src/app.ts`, `lerConfig` de `infraestrutura/config.ts` e `emTransacao`/`banco/index.ts` (TP-0003); `vercel.json` da raiz (TP-0004, só acrescentar o bloco `headers`); `EsquemaErro` de `@tdc/contrato` (TP-0017); `Relogio`/`relogioDoSistema` de `dominio/relogio` (TP-0011) para o `instante`; `test/apoio/banco-teste.ts` (TP-0009). O tratador de 500 que o TP-0003 deixou em `app.ts` é **movido** para o módulo novo, não duplicado; o código do erro passa a ser `erro_interno`, como em `.md/mockup/respostas/erro-servidor.json`.
**Camada:** `rotas/middleware/cabecalhos.ts` (lista única `CABECALHOS_SEGURANCA`), `rotas/middleware/borda.ts` (308, cabeçalhos, `X-Versao-App`, CSRF), `rotas/middleware/erro.ts` (`onError`); `aplicacao/erros/registrar-erro-api.ts` (rota não importa banco, G-10); `infraestrutura/banco/erros.ts` (`erros.registrar`, só INSERT parametrizado). Testes em `test/rotas/borda.test.ts` (unitário) e `test/integracao/rotas/erro.test.ts`.
**Referência visual:** não se aplica.

1. TDD: testes da Seção 2 primeiro.
2. `CABECALHOS_SEGURANCA`: CSP `default-src 'self'; img-src 'self' data:; object-src 'none'; base-uri 'none'; frame-ancestors 'none'`, `Strict-Transport-Security: max-age=31536000`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Permissions-Policy: camera=(), microphone=(), geolocation=()`. `vercel.json`: `headers: [{ source: "/(.*)", headers: [...] }]` com os mesmos pares.
3. Ordem no `criarApp`: 308 por host → cabeçalhos + `X-Versao-App` (`config.versaoApp`) aplicados a toda resposta, inclusive 308, 403 e 500 → CSRF → rotas. `onError` global.
4. 308: só quando o ambiente é produção e o `Host` difere do host de `ORIGEM_PUBLICA`; `Location` = origem + caminho + query. Previews nunca redirecionam (ADR-006 item 5).
   PENDENTE: como a API sabe que é produção? Proposta: `lerConfig` passa a ler `VERCEL_ENV` (opcional, só `production` liga o 308) e o `.env.example` ganha a variável. Depende também do PENDENTE do TP-0004 (redirect só no `vercel.json` ou reforço aqui).
5. CSRF (POST, PUT, PATCH, DELETE): `Origin` igual, string exata, a `ORIGEM_PUBLICA`, e media type de `Content-Type` = `application/json` (parâmetros como `charset` aceitos). Senão, 403 `{erro:"origem_invalida", mensagem}` no `EsquemaErro`. DELETE sem corpo também precisa do cabeçalho: registrar em `## 4` para o cliente do PWA (TP-0063) sempre enviá-lo. GET, HEAD e OPTIONS passam.
6. `onError`: chama `registrarErroApi({ rota: c.req.routePath, codigo, mensagem, instante })` e responde 500 `{erro:"erro_interno", mensagem:"Algo deu errado do nosso lado. Tente de novo em instantes."}`. `mensagem` gravada = nome da classe do erro + SQLSTATE quando houver (até 300). **Nunca** `err.message` do driver (o `detail` do Postgres traz valores), corpo, query, cabeçalho, cookie ou IP. Se gravar falhar, responde o mesmo 500 e só faz `console.error` do nome.
7. Não fazer: domínio literal no código (G-01); `crons` no `vercel.json`; tocar no middleware de sessão (TP-0023).

## 2. Plano de teste
- Unitário (`app.request` com config de teste): toda resposta (200 de `/api/situacao`, 403, 308, 500) tem os 5 cabeçalhos e `X-Versao-App`; HSTS sem `includeSubDomains`/`preload`.
- `vercel.json`: o teste lê o arquivo da raiz e confere que o bloco `/(.*)` tem exatamente os pares de `CABECALHOS_SEGURANCA` (falta, sobra ou valor diferente → falha).
- CSRF, matriz adversarial (CONVENCOES §9): sem `Origin`; `Origin: null`; `https://tarefas-da-casa-ljs.vercel.app.evil.com`; origem com `/` no fim; `http://` em vez de `https://`; caixa diferente; `Content-Type` ausente, `text/plain`, `application/jsonx`, `text/plain; a=application/json` → 403. `application/json; charset=utf-8` com origem certa → passa. GET sem `Origin` → passa. A origem vem do config de teste, nunca do valor de produção.
- 308: produção + host da URL por deploy → 308 com `Location` certo e query preservada; produção + host certo → segue; preview + host diferente → segue.
- Integração (banco descartável do TP-0009): rota registrada só no teste lança `new Error('bia@exemplo.com senha123')` → 500 igual ao `EsquemaErro`, com `erro_interno`; uma linha em `registro_erro` com `origem='api'`, rota no padrão (`/api/...`), sem o e-mail nem `senha123`; instante = relógio fixo. Banco fora do ar → 500 do mesmo jeito.
- Comandos: `pnpm --filter @tdc/api test -- test/rotas/borda` e `pnpm test:integracao -- erro`.
