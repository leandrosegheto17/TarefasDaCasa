## 1. Plano de execução
**Reaproveitamento:** USAR a tabela `codigo_vinculo` (TP-0006: `id`, `membro_id`, `tipo`, `codigo_hash` único, `criado_por`, `expira_em`, `usado_em`, `invalidado_em`); o tipo `Transacao` e `emTransacao` de `banco/conexao.ts` (TP-0003); `gerarCodigoVinculo` e `hashSha256` de `infraestrutura/token.ts` (TP-0021), só nos testes (o módulo recebe o hash pronto); fábricas e banco descartável de `test/apoio/` (TP-0009).
**Camada:** `backend/api/src/infraestrutura/banco/codigos.ts`, exportado pelo `banco/index.ts` sem expor a conexão. Teste em `test/integracao/banco/codigos.test.ts`.
**Referência visual:** não se aplica.

1. TDD: testes da Seção 2 primeiro.
2. `gravarInvalidandoAnteriores({ membroId, tipo, codigoHash, criadoPor, expiraEm, agora }, transacao?)`: um comando só, `WITH invalidados AS (UPDATE codigo_vinculo SET invalidado_em = $agora WHERE membro_id = $m AND usado_em IS NULL AND invalidado_em IS NULL) INSERT … RETURNING id, expira_em`. Atômico sem precisar de transação aberta aqui (a transação só se abre em `aplicacao/`).
3. `consumir(codigoHash, agora, transacao?)`: `UPDATE codigo_vinculo SET usado_em = $agora WHERE codigo_hash = $h AND usado_em IS NULL AND invalidado_em IS NULL AND expira_em > $agora RETURNING membro_id, tipo`; devolve `{ membroId, tipo }` ou `null`. Duas diferenças do texto do aceite, a registrar em `## 4`: `$agora` do relógio injetado no lugar de `now()` (G-13, testes com relógio fixo) e `invalidado_em IS NULL` (o código invalidado por outro mais novo não pode valer, CA-06.2). Aceita a `Transacao` para o TP-0030 consumir e criar a sessão na mesma transação (ADR-004 item 2).
4. `apagarAntigos(agora)`: apaga as linhas com `expira_em < $agora - interval '1 day'` (o SDD §5 diz "mais de 1 dia"; a tabela não tem `criado_em`, então a referência é a expiração, que é a criação + 10 min). Chamado depois pela rotina diária.
5. Não fazer: hash ou geração de código aqui (é do `token.ts`); conferir se o membro foi removido (é do caso de uso do TP-0030, registrar o aviso em `## 4`); `SELECT` seguido de `UPDATE` (abre corrida).

## 2. Plano de teste
Integração no banco descartável, relógio fixo, membros das fábricas, apagando o que criar:
- `gravarInvalidandoAnteriores`: gerar A e depois B para o mesmo membro → A com `invalidado_em`, B ativo; um código já usado do membro não é tocado; código de outro membro não é tocado.
- `consumir`: código válido → `{membroId, tipo}` e `usado_em` = relógio; segunda vez → `null`; expirado (`expira_em` = agora) → `null`; invalidado → `null`; hash desconhecido → `null`.
- Concorrência: o mesmo hash consumido por `Promise.all` em duas conexões diferentes (pool com 2 ou mais conexões) → exatamente um resultado não nulo; repetir 20 vezes para não passar por sorte.
- `apagarAntigos`: linha expirada há 25 h apagada; expirada há 23 h e ativa mantidas.
- Comando: `pnpm test:integracao -- codigos`.

- G-17: só `codigo_hash` vai ao banco; nenhum código em claro em log ou erro.
- G-05: SQL parametrizado só neste arquivo; conexão não exportada. G-13: sem `now()` em regra. G-28.
