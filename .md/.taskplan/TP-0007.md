## 1. Plano de execução
**Reaproveitamento:** USAR `scripts/migrar.ts` e `checar-migracoes` (TP-0005). As FKs apontam para `familia` e `membro` de `001_acesso.sql` (TP-0006).
**Camada:** `backend/api/migracoes/002_rotina.sql`. Teste em `backend/api/test/integracao/schema/rotina.test.ts`.
**Referência visual** (só tela/componente): não se aplica

1. `tarefa`: `id`, `familia_id` FK (ER), `nome` com CHECK de 1 a 60, `tipo_periodicidade` com CHECK em (`dias`, `semanal_flexivel`), `dias_semana smallint`. CHECK: quando `tipo='dias'`, `dias_semana between 1 and 127`; quando `semanal_flexivel`, `dias_semana is null`. Depois `atribuido_membro_id` FK nulável, `criada_em`, `arquivada_em`, `gerado_ate date`.
2. `ocorrencia`: `id`, `tarefa_id` FK `on delete restrict`, `data_prevista date`, `atribuido_membro_id` (cópia), `estado` com CHECK nos 3 valores. **Não existe** `atrasada` (ADR-003). Depois `credito_membro_id`, `registrado_por_membro_id`, `marcado_em`, `motivo_pulo` com CHECK de até 80, e `unique (tarefa_id, data_prevista)`.
3. CHECK de coerência: `(estado='pendente') = (credito_membro_id is null and registrado_por_membro_id is null and marcado_em is null)`. Além disso, `motivo_pulo is null` quando o estado é `pendente`.
4. Gatilho `BEFORE DELETE FOR EACH ROW`: dispara exceção se `OLD.estado <> 'pendente'`. Mais um `BEFORE TRUNCATE FOR EACH STATEMENT` que sempre recusa, porque o TRUNCATE não dispara gatilho de linha e furaria a G-07.
5. Índice de apoio para a leitura do Hoje: `(data_prevista)` e `(estado)` só se a consulta do lote 7 pedir. Não antecipar.
- NÃO apagar marcada nem permitir UPDATE de `concluida` para `pulada` no banco. Essa transição é regra de domínio (RN-02, TP-0011), não de schema.

## 2. Plano de teste
- Integração (Vitest contra o Postgres local, banco descartável), cada caso numa transação revertida:
  - `dias` com `dias_semana` 0, 128 ou nulo falha; 1 e 127 passam;
  - `semanal_flexivel` com máscara falha;
  - nome de 0 ou 61 caracteres falha;
  - estado `atrasada` falha;
  - `pendente` com `marcado_em` falha; `concluida` sem `registrado_por_membro_id` falha;
  - `motivo_pulo` de 81 caracteres falha;
  - duplicata `(tarefa_id, data_prevista)` falha;
  - DELETE de `pendente` passa; DELETE de `concluida` e de `pulada` falha;
  - TRUNCATE de `ocorrencia` falha;
  - DELETE da tarefa com ocorrência falha (restrict).
- Datas do teste derivadas de um instante fixo (CONVENCOES §7), nunca de `new Date()`.
- Migrar duas vezes (a segunda sem efeito) e `pnpm checar`. Comando: `pnpm --filter @tdc/api exec vitest run test/integracao/schema/rotina.test.ts` (ou `test:integracao`, conforme o PENDENTE).
