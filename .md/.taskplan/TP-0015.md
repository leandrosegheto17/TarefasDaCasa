# TP-0015 — `dominio/estados`: transições da ocorrência e desfazer

Reserva: Livre
ID no TASK.md: TP-0015 · Lote: Lote 3 · Agente: executor · Chapéu: Backend · Est: 1 h · Dep: TP-0011 · Status no TASK.md: Pendente
Reqs: RN-02, RN-11; ADR-003 · Aceite: Transições permitidas (Pendente → Concluída ou Pulada; Atrasada derivada da data; sem Concluída ↔ Pulada direta) e desfazer só se `marcado_em` estiver no período aberto, voltando para Pendente ou Atrasada conforme a data; teste de cada transição permitida e proibida

## 1. Plano de execução
**Reaproveitamento:** USAR de `backend/api/src/dominio/relogio.ts` (TP-0011) `hoje`, `semanaDe`, `ehAtrasada` e `DataCivil`. "Período aberto" = `semanaDe(hoje(marcadoEm))` igual a `semanaDe(hoje(agora))`, sem refazer conta de semana.
**Camada:** domínio puro, `backend/api/src/dominio/estados.ts`. Teste em `backend/api/test/dominio/estados.test.ts`. Quem decide **quem** pode desfazer é `dominio/permissoes` (TP-0016); este módulo decide só **quando**. O caso de uso (TP-0053, TP-0055, TP-0056) combina os dois.
**Referência visual:** não se aplica.

1. Tipos: `EstadoGravado = 'pendente' | 'concluida' | 'pulada'` (banco, ADR-003 item 2) e `EstadoExibido = EstadoGravado | 'atrasada'` (contrato, `.md/mockup/respostas/hoje-leo.json`).
2. `estadoExibido(oc, hoje)`: `pendente` com `ehAtrasada(dataPrevista, hoje)` → `atrasada`; resto igual ao gravado.
3. `podeMarcar(oc)` / `marcar(oc, { tipo: 'concluir' | 'pular', ... })`: permitido só de `pendente` (o que cobre Pendente e Atrasada exibidas); de `concluida`/`pulada` → erro de domínio `ja_marcada` (mesmo código de `.md/mockup/respostas/ocorrencia-conflito.json`). Concluída ↔ Pulada direta cai aqui. Atrasada de semana já fechada pode ser marcada (RN-10). Devolve só a mudança de estado; preencher autor/crédito/instante é do caso de uso.
4. `podeDesfazerNoPeriodo(oc, agora)`: só `concluida`/`pulada` com `marcadoEm` na semana corrente; `pendente` → erro `nao_marcada`; fora do período → `periodo_fechado`. `desfazer(oc, agora)` devolve `pendente` com `marcadoEm`, `registradoPor`, `credito` e `motivoPulo` nulos (coerente com o CHECK do TP-0007) e o `estadoExibido` resultante (Pendente ou Atrasada pela data, RN-11).
5. TDD: testes primeiro (tabela de transições). Arquivo ≤ ~120 linhas.
- NÃO: gravar `atrasada` em nenhum lugar; checar papel ou autoria aqui; criar texto de mensagem (é do contrato/rota).
   PENDENTE: os códigos `nao_marcada` e `periodo_fechado` não existem nos JSON do mockup (só `ja_marcada`). Confirmar os códigos de erro do desfazer com o contrato (TP-0019) ou reaproveitar `ja_marcada`.

## 2. Plano de teste
Unitário Vitest, tabela parametrizada, relógio fixo (hoje = qua 14/10/2026; semana 12 a 18/10):
- Permitidas: pendente (prevista hoje) → concluir/pular; pendente exibida como atrasada (prevista 12/10) → concluir/pular; atrasada da semana anterior (prevista 09/10) → concluir (RN-10).
- Proibidas: concluida → concluir, concluida → pular, pulada → concluir, pulada → pular (todas `ja_marcada`); desfazer em pendente.
- `estadoExibido`: prevista hoje → pendente; ontem → atrasada; concluída ontem → concluida.
- Desfazer: marcada seg 12/10 00:00:00 SP → permitido, volta `atrasada` (prevista 12/10) ou `pendente` (prevista 16/10); marcada dom 11/10 23:59:59 SP → `periodo_fechado`; conclusão tardia marcada hoje de ocorrência do dia 09/10 → permitido, volta `atrasada`.
- Campos de marcação nulos depois do desfazer.
Comando: `pnpm --filter @tdc/api exec vitest run test/dominio/estados.test.ts`. Cobertura: 100% de `estados.ts`.

## 3. Plano de validação de segurança
Sem superfície externa. RN-11 é proteção do placar (I2): verificar que não há caminho para desfazer marcação de semana fechada e que a borda dom 23:59:59 × seg 00:00:00 está testada. Import só de `dominio/` (G-10); `agora` sempre por argumento (G-13).
