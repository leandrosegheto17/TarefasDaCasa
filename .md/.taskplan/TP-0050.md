## 1. Plano de execução
**Reaproveitamento:** USAR `infraestrutura/banco/sessoes.ts` (TP-0023), acrescentando `revogar(id, agora)`; o 401 da próxima requisição já vem do `resolverSessao`/middleware de sessão (TP-0023), que recusa `revogada_em` preenchida: não repetir a checagem aqui. Se o `POST /api/sair` ou o `DELETE /api/membros/{id}` (TP-0047) já tiverem criado uma função de revogação em `banco/sessoes`, USAR a mesma. `podeAgir(ator, 'gerenciar_aparelhos')` (TP-0016) via `exigirPermissao` (ver TP-0048); `IdParametro` do `contrato/base` (TP-0017); `c.get('sessao')`; `Relogio` (TP-0011).
**Camada:** `aplicacao/acesso/revogar-aparelho.ts`; `infraestrutura/banco/sessoes.ts` (função nova); rota em `rotas/membros.ts` (o SDD §2.6 põe a rota no grupo Membros; encaixe aditivo). Teste em `test/integracao/rotas/aparelhos-revogar.test.ts`.
**Referência visual:** não se aplica.

1. TDD: teste de integração primeiro.
2. Rota: `{id}` por `IdParametro` (400 antes da consulta). O DELETE vai sem corpo, mas o CSRF da borda (TP-0022) exige `Origin` e `Content-Type: application/json` (nota do TP-0022 para o cliente do PWA).
3. `revogarAparelho(ator, sessaoId, { relogio })`: `exigirPermissao(ator, 'gerenciar_aparelhos')` (403 `sem_permissao`) → `sessoes.revogar`: um único `UPDATE sessao_aparelho SET revogada_em = $agora WHERE id = $id AND revogada_em IS NULL RETURNING id`. Sem linha (inexistente ou já revogada) → 404 `nao_encontrada` (códigos propostos no TP-0039). Sucesso → 204 sem corpo.
4. Revogar o próprio aparelho é permitido (equivale a sair); registrar em `## 4`.
- NÃO: `SELECT` antes do `UPDATE`; apagar a linha (o histórico de aparelhos fica); revogar outras sessões do membro.

## 2. Plano de teste
Integração (banco descartável, relógio fixo, fábrica `criarSessao` que devolve o token cru, TP-0023, e apaga o que cria):
- CA-08.2: Responsável R revoga a sessão da Criança C → 204; `revogada_em` = relógio fixo; a requisição seguinte de C, com o cookie dela, a uma rota protegida (registrada só no teste, como no TP-0023) → 401 `sessao_encerrada`; a sessão de R continua valendo.
- Revogar de novo → 404; UUID inexistente → 404; id `a-01` → 400.
- Criança tentando revogar a sessão de outra → 403 e a sessão alvo segue ativa; sem cookie → 401; sem `Origin` ou sem `Content-Type` → 403 (borda).
- R revoga a própria sessão → 204 e a próxima requisição dele → 401.
- Comando: `pnpm test:integracao -- aparelhos-revogar`.

## 3. Plano de validação de segurança
- RNF-09 / CA-08.2: revogação no servidor, efetiva na requisição seguinte (o middleware lê `revogada_em` a cada pedido, sem cache de sessão).
- G-16: 403 no caso de uso; ator só da sessão; o `{id}` é o alvo.
- G-19: DELETE passa pela checagem de `Origin`/`Content-Type`. CONVENCOES §8: UUID antes da consulta. G-05, G-10, G-13, G-28.
