## 2. Plano de teste
- Os três fluxos acima, em sequência no mesmo arquivo (o 3 depende do 2), contexto de celular (viewport do UX-SPEC) em Chromium.
- Borda: o fluxo 1 confere que o código vale uma vez (segunda tentativa com o mesmo código mostra o erro de T04); o fluxo 2 confere que o botão fica `aria-busy` até a resposta.
- Contagem final das tabelas igual à inicial antes do `apagarBanco` (prova de que o que foi criado foi limpo).
- Comandos: `docker compose -f backend/api/docker-compose.teste.yml up -d` e `pnpm test:e2e`; link do run verde do job `e2e` em `## 4`. Rodar só esse alvo, não a suíte inteira.

## 3. Plano de validação de segurança
- G-08: o banco do e2e passa pela `trava-host-local` (via `banco-teste`); nenhum caminho aceita host remoto.
- Segredos de teste (`CODIGO_INSTALACAO`, senha do Postgres do serviço) só de teste e marcados assim; `gitleaks` verde.
