## 2. Plano de teste
Vitest + Testing Library + `user-event`, `*.test.tsx` ao lado de cada componente (mesmo ambiente `jsdom` do TP-0066; quem chegar primeiro instala e registra).
- `Botao`: cada variante aplica a classe; `enviando` → `aria-busy=true`, `i-carregando`, nome acessível igual, segundo clique não chama `onClick`; `desabilitado` → `disabled`; `para` → `role=link` com `href` relativo.
- `CampoTexto`: `getByLabelText` acha o campo; ordem DOM instrução → input → erro → regra; com erro, `aria-invalid=true` e `aria-describedby` = `x-erro x-regra`; sem erro, sem `aria-invalid`. Senha: botão "Mostrar senha" com `aria-pressed=false` → clique → `type=text` e `aria-pressed=true`; `somenteLeitura` → `readonly` e botão desabilitado.
- `formatarCodigoDigitado` (tabela): `k7mp3rxw` → `K7MP-3RXW`; colar `k7mp 3rxw` e ` K7MP-3RXW ` → `K7MP-3RXW`; 12 caracteres → corta em 8; vazio → vazio; `abc` → `ABC`; hífens repetidos somem. Campo código com `autocomplete=one-time-code`, `autocapitalize=characters`, `spellcheck=false`, `maxlength=9`.
- `Alerta`: erro → `role=alert`; info com `papel=status` → `role=status`. `Nota` com o ícone `aria-hidden`.
- Classes só do `base.css`, pelo utilitário `frontend/test/apoio/classes-base.ts` (combinado com o TP-0066: quem chegar primeiro cria).
- `Dialogo`/`FolhaInferior`: abrir a partir de um botão → `getByRole('alertdialog'|'dialog')` com `aria-modal=true` e nome = título; foco no título; Esc → `aoCancelar`/`aoFechar`; "Cancelar" idem; ao fechar, foco no botão de origem; Tab no último elemento volta ao primeiro; ação perigo tem `.botao--perigo`.
Comando: `pnpm --filter @tdc/pwa exec vitest run src/componentes src/formatacao/codigo-vinculo`.
