# TP-0097 — Publicação de produção: conferência de ambiente e workflow de deploy com migração

Reserva: Livre

Reqs: ADR-006 item 6; SDD §6 Troca de dados (migração); RT-11 · Aceite: `scripts/conferir-ambiente.ts` roda no build de produção e falha se `ORIGEM_PUBLICA` estiver vazia ou diferente de `https://tarefas-da-casa-ljs.vercel.app`, se `VERCEL_PROJECT_PRODUCTION_URL` não for `tarefas-da-casa-ljs.vercel.app` ou se faltar variável; em Preview, falha se o host da `DATABASE_URL` for o do branch de produção (`NEON_HOST_PRODUCAO`, só o host, sem segredo); `deploy.yml` na `main`: dispara o backup, cria um branch de segurança do Neon, roda `migrar --producao` com o papel dono e só então libera o deploy da Vercel; `actionlint` + checagem no CI de que a ordem dos passos é backup → branch → migração → deploy; procedimentos de volta atrás e de "nova origem" (RT-11) no `.md/DEPLOY.md`

## 1. Plano de execução
**Reaproveitamento:** USAR `lerConfig(env)` de `infraestrutura/config.ts` (TP-0003) para "faltar variável" (não listar as variáveis de novo); a leitura de host de `infraestrutura/banco/host-local.ts` (TP-0003; se só existir `ehHostLocal`, EXTRAIR `hostDe(url)` ali e usar nos dois); `scripts/migrar.ts` + `trava-host-local` (TP-0005), com o critério sem TTY do PENDENTE do TP-0005 adotado: `GITHUB_ACTIONS=true` + `GITHUB_REF=refs/heads/main` + `GITHUB_WORKFLOW=deploy` (por isso o `name:` do workflow é exatamente `deploy`); `backup.yml` por `workflow_call` (TP-0096), sem segundo dump; `vercel.json` (TP-0004/TP-0022, só acrescentar); padrão de guarda da raiz (`scripts/guarda-id-tarefa.mjs`, TP-0002) e o script `checar`.
**Camada:** `backend/api/scripts/conferir-ambiente.ts` (função pura `conferirAmbiente(env)` → lista de erros + entrada fina; único arquivo com o domínio literal, G-01 e exceção do TP-0071); `.github/workflows/deploy.yml`; `scripts/checar-ordem-deploy.mjs` na raiz; passos novos no `ci.yml`; seções no `.md/DEPLOY.md` (TP-0095/0096 escrevem em paralelo: reler antes).
**Referência visual:** não se aplica

Feito pelo agente:
1. TDD de `conferirAmbiente`: só age com `VERCEL=1`; `VERCEL_ENV=production` → `lerConfig` + `ORIGEM_PUBLICA` exata + `VERCEL_PROJECT_PRODUCTION_URL` exata; `preview` → `NEON_HOST_PRODUCAO` presente e ≠ host da `DATABASE_URL`; `VERCEL_ENV` ausente ou desconhecido com `VERCEL=1` → falha. Mensagem cita nome da variável, nunca o valor de URL com senha.
2. `vercel.json`: `buildCommand` passa a rodar `conferir-ambiente` antes do build do PWA; `"git": {"deploymentEnabled": {"main": false}}` para a `main` só publicar pelo workflow (previews seguem automáticos).
3. `deploy.yml` (`name: deploy`, `on: push: branches: [main]` + `workflow_dispatch`, `concurrency: deploy-producao` sem cancelar, `permissions: contents: read`, `environment: producao`). Jobs encadeados por `needs`: `ci` (o `ci.yml` ganha `workflow_call`) → `backup` (`uses: ./.github/workflows/backup.yml`, `secrets: inherit`) → `branch-seguranca` (API do Neon por `curl` com `NEON_API_KEY`/`NEON_PROJECT_ID`: cria `seguranca-<sha7>` a partir do branch de produção e apaga os `seguranca-*` além dos 3 mais novos, pelo limite de branches do Free) → `migracao` (install congelado + `migrar --producao` com `DATABASE_URL_MIGRACAO`) → `deploy` (`npx --yes vercel@<versão fixa> deploy --prod --token "$VERCEL_TOKEN"`, build remoto na Vercel, onde `conferir-ambiente` roda com as variáveis de sistema) → `curl -fsS https://.../api/situacao` conferindo `X-Versao-App`.
4. `scripts/checar-ordem-deploy.mjs` (função pura + entrada, no `checar` e no CI) e passo `actionlint` (binário oficial em versão fixa) no job `base` do `ci.yml`.
PENDENTE: ler o YAML exige parser. Proposta: `yaml` como devDependency da raiz (altera lockfile, registrar), em vez de regex sobre o texto. Confirmar com o Coordenador.
5. `DEPLOY.md`: "Publicação" (o que o workflow faz, secrets), "Volta atrás" (Vercel > Deployments > Instant Rollback para o código; para o schema, restaurar o `seguranca-<sha7>` no Neon ou o dump do TP-0096; como a migração é aditiva, G-06, o código anterior roda sobre o schema novo), "Nova origem (RT-11)": novo projeto/origem → `ORIGEM_PUBLICA`, `conferir-ambiente` e ADR-006 atualizados, reinstalar e gerar código para todos os aparelhos.

Feito pelo usuário: GitHub > Environments > `producao` (só `main`) com secrets `DATABASE_URL_MIGRACAO`, `NEON_API_KEY`, `NEON_PROJECT_ID`, `VERCEL_TOKEN`, `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID`; Vercel > Settings > Environment Variables: `NEON_HOST_PRODUCAO` (só o host) em Preview e Production; depois do primeiro run verde, remover `DATABASE_URL_MIGRACAO` das variáveis da Vercel (a função não usa o papel dono). Evidência: link do run com os 6 jobs na ordem, `curl -I` da origem e saída do `/api/situacao`, sem segredo.

- Comandos: `pnpm --filter @tdc/api exec vitest run test/unit/conferir-ambiente.test.ts`, `pnpm vitest run scripts/checar-ordem-deploy`, `actionlint`, `pnpm checar`.

## 3. Plano de validação de segurança
- G-01/G-02/G-03/G-04/G-08 são checadas por esta tarefa: conferir que só `conferir-ambiente.ts` tem o domínio e que `migrar --producao` só aparece no `deploy.yml`.
- Workflow: secrets só no environment `producao` e em `env:` (nunca no `run:` interpolado, nunca em `echo`); `permissions: contents: read`; gatilho só `push` na `main` e manual (sem `pull_request`); versão fixa do CLI da Vercel; `NEON_HOST_PRODUCAO` não é segredo e não leva usuário/senha.
- Menor privilégio: papel dono só no job `migracao`; a função na Vercel fica só com `tdc_app`.
- HSTS e cabeçalhos seguem no `vercel.json` (TP-0022): a edição do `buildCommand`/`git` não pode remover o bloco `headers` nem o redirect 308; `checar-dependencias` (TP-0010) continua sem `crons`.
