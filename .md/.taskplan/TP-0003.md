# TP-0003 — Esqueleto da API: configuração, conexão, app Hono, entradas e rota mínima de situação

Reserva: Livre
ID no TASK.md: TP-0003 · Lote: Lote 1 · Agente: executor · Chapéu: Backend · Est: 2,5 h · Dep: TP-0001 · Status no TASK.md: Pendente
Reqs: SDD §2.1, §2.2, Pacotes e fronteiras; ADR-001, ADR-002 · Aceite: `infraestrutura/config.ts` valida na partida `DATABASE_URL`, `ORIGEM_PUBLICA`, `CODIGO_INSTALACAO` e `VERSAO_APP` (mensagem clara e saída com erro se faltar); `infraestrutura/banco/conexao.ts` com `postgres` (`prepare: false`, TLS) e `emTransacao(fn)`, sem exportar a conexão; app Hono com `GET /api/situacao` mínimo (`{ versaoApp }` depois de um `select 1` pelo módulo de dados); `entradas/vercel.ts` e `entradas/servidor-node.ts` só montam o app; testes unitários do config; `servidor-node` responde contra um Postgres local; variáveis no `backend/.env.example`

## 1. Plano de execução
**Reaproveitamento:** USAR o pacote `@tdc/api` (`backend/api`), o `tsconfig` base e o Vitest do TP-0001; ATUALIZAR `backend/.env.example` (já criado no TP-0001), sem criar outro. A checagem "host é local" criada aqui fica num módulo próprio para a `trava-host-local` do TP-0005 USAR, não reescrever.
**Camada:** `backend/api/src/infraestrutura/config.ts`; `infraestrutura/banco/conexao.ts`, `banco/saude.ts`, `banco/host-local.ts`, `banco/index.ts`; `aplicacao/situacao.ts`; `rotas/situacao.ts`; `src/app.ts` (monta o Hono); `entradas/vercel.ts`, `entradas/servidor-node.ts`.

1. `config.ts`: `lerConfig(env)` pura (recebe o objeto de ambiente, testável) devolve `{ databaseUrl, origemPublica, codigoInstalacao, versaoApp }` ou lança erro listando **todas** as variáveis ausentes/inválidas. `DATABASE_URL` com esquema `postgres(ql)://`; `ORIGEM_PUBLICA` só origem (sem caminho), `https://`, ou `http://` apenas para `localhost`. Sem domínio literal (G-01). O limite 16 a 64 do `CODIGO_INSTALACAO` nasce em `backend/contrato/src/limites.ts` (TP-0017); aqui só presença.
2. `banco/conexao.ts`: cria a conexão `postgres(url, { prepare: false, ssl: 'require', max: <pequeno> })` de forma preguiçosa e reaproveitada entre invocações; TLS desligado só quando `ehHostLocal(url)` (Postgres local do teste). `emTransacao(fn)` via `sql.begin`, passando um tipo opaco `Transacao` que as funções por agregado vão aceitar. `banco/index.ts` exporta `emTransacao`, `saude.verificar()` (`select 1`) e `encerrar()`; **nunca** `sql` (G-05).
3. `aplicacao/situacao.ts`: `obterSituacao({ versaoApp })` chama `saude.verificar()` e devolve `{ versaoApp }`. A rota não importa `infraestrutura/banco` (SDD: rota → aplicacao).
4. `rotas/situacao.ts`: `GET /api/situacao` chama o caso de uso. `app.ts`: `criarApp(config)` registra as rotas; erro não tratado → `500 {"erro":"interno","mensagem":"…"}` sem pilha (formato SDD §2.6). `registro_erro`, cabeçalhos e `X-Versao-App` ficam para o TP-0022.
5. `entradas/servidor-node.ts`: `lerConfig(process.env)`; em erro imprime a mensagem e `process.exit(1)`; serve `criarApp`. `entradas/vercel.ts`: exporta o handler do mesmo app. Nenhuma regra nas entradas; entrada não importa entrada.
6. `backend/.env.example`: as quatro variáveis com valores fictícios e comentário de formato; `backend/README.md`: como subir local (`docker run postgres:17` até o TP-0009) e `pnpm --filter @tdc/api dev`.

PENDENTE: rodar Hono como processo Node e como função exige um adaptador (`@hono/node-server`, também usado em `@hono/node-server/vercel`), que não está na tabela de dependências do SDD §2 (`@tdc/api` → `@tdc/contrato`, `hono`, `postgres`). Pode entrar como dependência de `@tdc/api`, ou o servidor deve ser montado só com `node:http` + `app.fetch`? O mesmo vale para validar o config: aqui é feito à mão, sem `zod` direto em `@tdc/api`.

## 2. Plano de teste
- Unitário `test/unit/config.test.ts`: tudo presente → objeto; cada variável ausente → erro que cita o nome; várias ausentes → todas citadas; `ORIGEM_PUBLICA` com caminho, com `http://` não local ou vazia → erro; `DATABASE_URL` sem esquema postgres → erro.
- Unitário `host-local.test.ts`: `localhost`, `127.0.0.1`, `::1` → local; `ep-x.sa-east-1.aws.neon.tech`, `localhost.evil.com`, URL malformada → não local.
- Teste de tipo: `banco/index.ts` não exporta a conexão (`expectTypeOf` sobre as chaves do módulo).
- Integração (Postgres 17 local, recusa host não local): `criarApp(config).request('/api/situacao')` → 200 `{ versaoApp }`; banco fora do ar → 500 genérico sem pilha.
- Manual: `servidor-node` com `.env` local + `curl -i localhost:<porta>/api/situacao`; sem `DATABASE_URL` → sai 1 com a mensagem. Registrar.
- Comandos: `pnpm --filter @tdc/api test`, `pnpm --filter @tdc/api typecheck`.

## 3. Plano de validação de segurança
- ADR-002/SDD §7: TLS obrigatório para host não local; `prepare: false`; SQL só em `infraestrutura/banco/` por tagged template (G-05).
- Conexão não exportada (G-05); rota sem import de banco (G-10).
- Mensagem de config cita **nomes** de variável, nunca o valor (não vazar `DATABASE_URL`/`CODIGO_INSTALACAO` no log). 500 sem pilha nem detalhe do driver.
- Nenhum domínio no código (G-01); `.env.example` sem valor real.
