## 1. Plano de execução
**Reaproveitamento:** USAR de `@tdc/contrato`: `EsquemaErro` (TP-0017), `ErroBloqueado` e `RespostaSituacao` (TP-0018), `RespostaHoje` e `ErroConflito` (`erro: 'ja_marcada'`, TP-0019), esquemas de placar (TP-0020). Nenhum tipo de resposta é redeclarado no front; tipos via `z.infer` do pacote. Respostas de exemplo nos testes: `.md/mockup/respostas/*.json` (lidas, não copiadas).
**Camada:** `@tdc/pwa`, `frontend/src/api/` (único lugar com `fetch`, Seção 1.2): `cliente.ts`, `ganchos.ts`, `versao.ts`; testes em `frontend/test/api/`.
**Referência visual:** não se aplica (sem tela; G1/G2 são desenhados por TP-0066/TP-0070).

1. TDD: `test/api/cliente.test.ts` e `test/api/ganchos.test.ts` primeiro, com `vi.stubGlobal('fetch', ...)`.
2. `cliente.ts`: `requisitar(caminho, esquema, { metodo, corpo, sinal })` → `Resultado<T>` = `{ ok: true, dados }` | `{ ok: false, falha }`. Sempre caminho relativo (`/api/hoje`, ADR-006), `credentials: 'same-origin'`, `Accept` e `Content-Type: application/json` (corpo `JSON.stringify`; o CSRF do TP-0022 exige o Content-Type). Resposta validada com `esquema.safeParse`; inválida → falha `servidor` (nunca mostra dado fora do contrato).
3. Mapa de falhas (`falha.tipo`): `TypeError` do fetch ou `503` com `erro: 'sem_conexao'` → `sem_conexao` (G1, C-12); `401` → `sessao_encerrada` + chama o ouvinte registrado por `aoSessaoEncerrada(fn)` (a navegação para `/entrar` com o aviso G2 é do shell, TP-0070); `409` com `erro: 'ja_marcada'` → `conflito` com `hoje: RespostaHoje`; outro 4xx com corpo `EsquemaErro` → `recusada` (repassa `erro`, `mensagem`, `campos`, `segundosRestantes`); 5xx ou corpo ilegível → `servidor`. Aborto pelo `sinal` não vira falha visível.
4. 409 e Hoje: adotar a proposta do TP-0019 (campo opcional `hoje` no corpo do 409). Se o corpo não trouxer `hoje` (caso de `ocorrencia-conflito.json`), o cliente faz um `GET /api/hoje` e entrega o resultado na falha `conflito`. PENDENTE (herdado do TP-0019): confirmar o campo `hoje` no 409; o fallback de nova busca fica até lá.
5. `versao.ts`: `conferirVersao(cabecalho)`: cabeçalho ausente (respostas do mockup na comparação visual) é ignorado; diferente da versão do build → grava a versão vista em `sessionStorage` e chama `recarregar()` (injetável, padrão `location.reload()`); se já recarregou para essa versão, não recarrega de novo (sem laço).
   PENDENTE: de onde vem a versão do build do PWA? O TP-0001 diz que o PWA não lê variável. Proposta: `vite.config.ts` injeta `__VERSAO_APP__` a partir de `process.env.VERSAO_APP` (a mesma variável da API, TP-0004 item 4), `'dev'` quando ausente, e com `'dev'` a conferência é desligada; `frontend/.env.example` passa a listá-la.
6. `ganchos.ts`: `usarConsulta(buscar, deps)` → `{ estado: 'carregando' | 'erro' | 'sucesso', dados, falha, tentarDeNovo }`; busca ao montar, ao mudar `deps`, em `tentarDeNovo` e em `visibilitychange` para `visible` (C-03, CA-18.2); `AbortController` por busca e no desmonte. Sem cache: os dados vêm só da última resposta; em erro, `dados` fica vazio (nenhum dado velho como atual, D-04/C-05). `usarAcao(executar)` → `{ executar, enviando, falha }`, sem atualização otimista (ADR-005, C-02); chamada repetida enquanto `enviando` é ignorada.
7. Testes de gancho precisam de `@testing-library/react` e `jsdom` como devDependencies do `@tdc/pwa` (lockfile; registrar em `## 4`; TP-0062/TP-0064 rodam em paralelo, reler antes).

Não fazer: React Query, Zustand, IndexedDB ou `localStorage` de dados (Seção 1.3); `fetch` fora de `api/`; texto de usuário aqui (G1/G2 usam `textos/`, TP-0064); decidir estado ou permissão (G-12).

## 2. Plano de teste
Vitest + jsdom, `fetch` simulado, respostas do mockup via leitura do JSON:
- Sucesso: `hoje-bia.json` validado devolve `ok: true`; a chamada usa `credentials: 'same-origin'`, caminho relativo e os dois cabeçalhos JSON; corpo serializado no POST.
- G1: `TypeError('Failed to fetch')` e `503` + `erro-sem-conexao.json` → `sem_conexao`. `503` com outro código → `servidor`.
- G2: `401` + `erro-sessao-encerrada.json` → `sessao_encerrada` e o ouvinte é chamado uma vez.
- 409: `ocorrencia-conflito.json` sem `hoje` → refaz `GET /api/hoje` e entrega `hoje-bia.json`; com `hoje` no corpo → não refaz. 409 com outro código → `recusada`.
- `recusada`: `criar-familia-erro.json` (com `campos`) e `entrar-email-bloqueado.json` (com `segundosRestantes`) repassados.
- Contrato: resposta 200 fora do esquema (campo faltando) → `servidor`; corpo não JSON → `servidor`.
- Versão: cabeçalho igual → nada; diferente → `recarregar` chamado uma vez; segunda resposta com a mesma versão nova → não chama de novo; ausente → nada.
- `usarConsulta`: carregando → sucesso; erro → `tentarDeNovo` → sucesso; `visibilitychange` (`visible`) refaz a busca, `hidden` não; desmontar aborta sem aviso de setState; troca de `deps` cancela a busca anterior (resposta velha não sobrescreve).
- `usarAcao`: `enviando` verdadeiro até a resposta; segundo clique ignorado; falha exposta e dados anteriores intactos.
Comando: `pnpm --filter @tdc/pwa exec vitest run test/api`. Cobertura: 100% de ramos de `cliente.ts` e `versao.ts`.

## 3. Plano de validação de segurança
- ADR-004/G-18: cookie só por `credentials: 'same-origin'`; nenhum token em JS, `localStorage` ou URL. ADR-006/G-01: nenhum domínio, só caminho relativo.
- G-19: todo método que altera manda `Content-Type: application/json` (o servidor exige; teste confere).
- ADR-005/G-25: nenhum dado persistido (conferir no diff: só `sessionStorage` com a versão vista, sem dado da família).
- Validação de resposta pelo esquema do contrato (CONVENCOES §8, lado do cliente); mensagem de erro do servidor nunca é exibida crua sem passar por `EsquemaErro`.
- Recarga por versão sem laço (teste acima); lint `no-restricted-globals: fetch` fora de `api/` continua passando.
