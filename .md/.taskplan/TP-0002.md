# TP-0002 — CI base no GitHub Actions

Reserva: Livre
ID no TASK.md: TP-0002 · Lote: Lote 1 · Agente: executor · Chapéu: Backend · Est: 2 h · Dep: TP-0001 · Status no TASK.md: Pendente
Reqs: Seção 1.5; CONVENCOES §4, §6; SDD §7 (`gitleaks`) · Aceite: `.github/workflows/ci.yml` em push e PR roda install congelado, `lint`, `format:check`, `typecheck`, `test` e `gitleaks`; passo `guarda-id-tarefa` falha se `TP-`, `RTP-`, `SPK-`, `BK-` ou "Lote N" aparecer em comentário ou string de `backend/` e `frontend/`, com matriz adversarial (comentário de bloco, minúsculas, dentro de template string, ferramenta ausente falha fechado); passo que falha se faltar `README.md` ou `.env.example` em `backend/` ou `frontend/`; cache do pnpm com caminho relativo à pasta onde o comando roda

## 1. Plano de execução
**Reaproveitamento:** USAR os scripts da raiz criados no TP-0001 (`pnpm lint`, `format:check`, `typecheck`, `test`) e a config do Vitest da raiz (`vitest-config`) para testar o guarda. O CI chama os scripts; não repete comandos de ESLint/tsc dentro do YAML.
**Camada:** `.github/workflows/ci.yml` (SDD árvore alvo); guardas em `scripts/` na raiz (ferramenta de repositório, fora de `backend/` e `frontend/`, para o guarda não acusar os próprios padrões). A árvore do SDD não lista `scripts/` na raiz: registrar em `## 4`.
**Referência visual:** não se aplica.

1. `scripts/guarda-id-tarefa.mjs` (Node 24, sem dependência): lista arquivos com `git ls-files --cached --others --exclude-standard -- backend frontend`; ignora binários (`.woff2`, `.png`, `.svg` de avatar continua texto e entra); procura, sem diferenciar maiúsculas, `\b(RTP|TP|SPK|BK)-\d+` e `\blote[\s ]+\d+`; imprime `arquivo:linha` e sai 1. Sai 1 também se `git` falhar ou se a lista vier vazia (falha fechado). Exporta a função de varredura de texto para o teste.
2. `scripts/checar-arquivos-obrigatorios.mjs`: falha se faltar algum de `backend/README.md`, `backend/.env.example`, `frontend/README.md`, `frontend/.env.example` (G-29).
3. Raiz `package.json`: script `checar` que roda os dois guardas (outros guardas entram depois nele: TP-0005, TP-0010, TP-0071).
4. `ci.yml`: `on: [push, pull_request]`; job `base` em `ubuntu-latest`: `actions/checkout` (`fetch-depth: 0` para o gitleaks ver o histórico), `pnpm/action-setup`, `actions/setup-node` com `node-version-file: .nvmrc`, `cache: pnpm`, `cache-dependency-path: pnpm-lock.yaml` (relativo à raiz, onde o install roda: CONVENCOES §6); depois `pnpm install --frozen-lockfile`, `pnpm lint`, `pnpm format:check`, `pnpm typecheck`, `pnpm test`, `pnpm checar`, e passo `gitleaks` (binário oficial ou `gitleaks/gitleaks-action`; conferir licença da action para conta pessoal).
5. Permissões mínimas no workflow (`permissions: contents: read`).

Ordem TDD: teste do guarda (matriz abaixo) → guarda → workflow. Não criar job de integração (TP-0009) nem de comparação visual (TP-0071). Não usar `continue-on-error`.

## 2. Plano de teste
`scripts/guarda-id-tarefa.test.mjs` (Vitest da raiz), sobre a função de varredura, com textos em memória (nada escrito em `backend/`):
- Acusa: `// TP-0001`, `/* bloco\n RTP-0003 */`, `{/* SPK-01 */}` (JSX), `"bk-12"`, `` `x ${a} Tp-0048` ``, `# Lote 3`, `lote 7`, `LOTE 12`.
- Não acusa: `const tpx = 1`, `HTTP-2`, `STP-12` (sem fronteira de palavra), `TP-` sem dígito, `"loteria"`, `lote` sem número.
- Falha fechado: `git` ausente (PATH vazio no processo filho) → sai 1; lista vazia → sai 1.
- `checar-arquivos-obrigatorios`: com os quatro → 0; removendo um numa pasta temporária → 1.
Rodar: `pnpm vitest run scripts/`. Prova do CI: push numa branch e registrar o link/resultado do run (verde), e um commit local de teste com `// TP-0001` em `backend/` fazendo `pnpm checar` sair 1 (desfeito antes de devolver).

## 3. Plano de validação de segurança
- G-17/SDD §7: `gitleaks` roda em push e PR e falha o job com segredo; conferir que não há `.gitleaksignore` amplo.
- Workflow: `permissions: contents: read`; nenhum `secrets.*` usado neste job; `pull_request` (não `pull_request_target`); actions fixadas por versão maior oficial.
- Guarda é guarda de segurança de processo (CONVENCOES §9): matriz adversarial acima obrigatória, falha fechado comprovada.
- G-28/G-29 passam a ser verificadas por este CI.
