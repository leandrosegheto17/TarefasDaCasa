## 1. Plano de execução
**Reaproveitamento:** usa só `tsconfig-base`/`vitest-config` do TP-0001. Nada de domínio a reaproveitar. O "período aberto" do desfazer é de `dominio/estados` (TP-0015): não repetir aqui. Este módulo é a fonte única de permissão para os casos de uso e para os campos `podePular`/`podeDesfazer`/`podeConcluirPorOutro` da resposta do Hoje (`.md/mockup/respostas/hoje-leo.json`), que a tela só mostra (G-12).
**Camada:** domínio puro, `backend/api/src/dominio/permissoes.ts`. Teste em `backend/api/test/dominio/permissoes.test.ts`.
**Referência visual:** não se aplica.

1. Tipos: `Ator = { id: string, papel: 'responsavel' | 'crianca' }` (sempre montado a partir da sessão, ADR-004); `OcorrenciaParaPermissao = { atribuidoMembroId: string | null, registradoPorMembroId: string | null }`.
2. `podePular(ator, oc)`: Responsável → true; Criança → `atribuidoMembroId === null || atribuidoMembroId === ator.id` (RN-12).
3. `podeDesfazer(ator, oc)`: Responsável → true; senão `registradoPorMembroId === ator.id` (autor = quem registrou, não o creditado do RF-25; SDD §5). Não checa período.
4. `exigeResponsavel(acao)`: união fechada `AcaoDeResponsavel` com uma chave por linha "Responsável só" da matriz do SDD §7: `concluir_por_outro`, `pular_pendencias_antigas`, `gerenciar_tarefas`, `gerenciar_membros`, `gerar_codigo`, `gerenciar_aparelhos`, `ver_atividade`. Mais `podeAgir(ator, acao)` que devolve `papel === 'responsavel'` para elas.
5. Falha fechada: papel fora da união ou ação desconhecida → false (sem `default: true`).
6. Se o H10 for cortado (TASK §5.2), só muda `podeDesfazer` (Criança sempre false), num ponto só.
7. TDD: tabela de testes primeiro. Arquivo ≤ ~80 linhas.
- NÃO: receber id de membro do corpo da requisição como ator; importar nada de fora de `dominio/`.

## 2. Plano de teste
Unitário Vitest, `it.each` com uma linha por linha da matriz do SDD §7 × papel (ids fixos `r1`, `c1`, `c2`):
- Ver Hoje/Casa/Semanas/Contribuições, concluir qualquer ocorrência e sair do próprio aparelho: os dois papéis podem (nenhuma está em `AcaoDeResponsavel`).
- `concluir_por_outro`, `pular_pendencias_antigas`, `gerenciar_tarefas`, `gerenciar_membros`, `gerar_codigo`, `gerenciar_aparelhos`, `ver_atividade`: Responsável sim, Criança não.
- `podePular`: Responsável em atribuída a `c1`/`c2`/Qualquer um → sim; `c1` em atribuída a `c1` → sim, a Qualquer um → sim, a `c2` → não, a `r1` → não.
- `podeDesfazer`: `r1` em marcação de `c1` → sim; `c1` na própria → sim; `c1` na de `c2` → não; `c1` creditada por `r1` (RF-25, `registradoPor = r1`) → não.
- Matriz adversarial (CONVENCOES §9): papel `'Responsavel'`/`'admin'`/`undefined` → false em tudo; ação desconhecida → false; `registradoPorMembroId: null` com Criança → false; id igual com maiúsculas diferentes → não confunde (comparação estrita); `atribuidoMembroId: undefined` não vira "Qualquer um" (só `null` vale).
Comando: `pnpm --filter @tdc/api exec vitest run test/dominio/permissoes.test.ts`. Cobertura: 100% de `permissoes.ts`.
