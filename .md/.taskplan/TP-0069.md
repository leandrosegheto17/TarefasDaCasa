Modo `botoes` (T07 passo 2): `ul.seletor-membro > li > button.opcao-membro` com avatar + apelido, `aoEscolher(id)`; sem "Qualquer um".
4. `ZonaPerigo({ explicacao?, children: ({ desabilitado, descritoPor }) => ReactNode })`: `div.zona-perigo`; com `explicacao` gera `p.explicacao` com id próprio (`useId`) e entrega `desabilitado: true` e `descritoPor` para a página pôr no `Botao` (`disabled` + `aria-describedby`). Quem decide se está desabilitada é a página, a partir do que a API manda (ex.: último Responsável, CA-05.3); o componente não decide regra.
Não fazer: ordenar membros, filtrar quem pode ser escolhido ou decidir permissão (G-12); botão próprio com as classes `.botao` (o slot existe para isso); CSS novo.

## 2. Plano de teste
Vitest + Testing Library + `user-event`, `*.test.tsx` ao lado de cada componente.
- `LinhaLista`: com `para` → `getByRole('link', {name: /Arrumar a cama.*Todos os dias · Bia/})` e seta `aria-hidden`; com `acao` → não é link, o botão passado é alcançável por `getByRole('button', {name: 'Reativar Tirar o pó da estante'})`; `avatar` aplica `.linha--avatar` e `alt=""`.
- `SeletorMembro` rádio: `getByRole('group', {name: 'Quem'})`; primeiro rádio "Qualquer um", marcado com `valor=null`; setas do teclado mudam a seleção e chamam `aoMudar` com o id; duas instâncias na mesma tela não compartilham `name`; sem `comQualquerUm` o item some; ordem dos membros igual à recebida.
- `SeletorMembro` botões: cada membro é `role=button` com o apelido no nome; clique chama `aoEscolher(id)`; não há rádio.
- `ZonaPerigo`: sem `explicacao` → `desabilitado=false`, sem `p.explicacao`; com `explicacao` → `getByRole('button')` desabilitado e `toHaveAccessibleDescription('Não dá para remover: a família precisa de pelo menos um responsável.')`.
- Classes só do `base.css` pelo utilitário do TP-0066.
Comando: `pnpm --filter @tdc/pwa exec vitest run src/componentes`.
